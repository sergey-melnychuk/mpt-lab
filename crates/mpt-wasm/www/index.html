Setting a currently-absent slot always works standalone — eth_getProof for a zero slot IS an exclusion proof, which is all an insert needs. Zeroing a slot usually works standalone too, UNLESS it collapses a Fork whose surviving sibling isn't in this witness: that one case fails with the exact node (hash + path) a public RPC cannot supply — see PTRIE.md §8 / PLAN.md §1. That's a real gap in what eth_getProof can express, not a bug in this page.

Solid cells in a Fork's strip are real and clickable; dashed ones are Stubs — nothing behind them to explore, so they don't respond to clicks. A proof for a SINGLE key only ever has one real nibble per Fork (everything else on that key's path is a Stub by construction), so most of a strip being non-interactive here is expected, not broken. Fetch more than one slot at once to get Forks with two-or-more real, clickable branches.
