Key/value pairs

i Each value is RLP-encoded (leading zero bytes trimmed) before insertion, like a real storage slot; a zero value instead removes the key, as SSTORE(slot, 0) does — Ethereum has no slot holding zero. With Hash checked, each key is also keccak256-hashed first — the "secure trie" transform Ethereum's real state and storage tries apply, so the shape you get matches what eth_getProof would return for the same data. Uncheck it to insert keys as raw bytes instead: keys sharing a hex prefix then share trie structure too, which makes Skip/Fork shapes easier to see than a keccak256 hash's uniform sprawl. Both inputs must be hex (0x-prefixed or not). With Trace checked, a change to one key is animated and a removal steps through the collapse it causes; unchecked, the tree simply updates. Clicking a Leaf on the tree, or a row's ›, points the one at the other.
